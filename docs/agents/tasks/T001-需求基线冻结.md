## 目标

从零收敛 AI 智能工作台首版需求，形成可执行、可逐项验收的需求基线，为后续 ZCode/Reasonix 拆解实现任务提供依据。

## 产品定位

- Windows 本地优先桌面应用。
- 首版给用户个人使用，数据模型预留多用户、角色、租户字段。
- 核心目标：减少多软件来回切换，解放重复整理、文档生产、排期、对账等工作时间。
- 用户一人承担产品、售前、解决方案、报价/功能清单、招投标、项目管理、产研负责人、运营、对账、测试、高保真/UI 原型等工作。

## 首版主线

统一收件箱 -> 项目档案 -> 售前/招投标文档初稿 -> 自动生成待办和 DDL。

## 数据与知识底座

- 以现有本地文件夹和 WPS 文件为基础。
- Obsidian Vault 作为知识底座，工作台直接读写 Markdown。
- Vault 位置独立于代码项目，例如 `D:\AI-Workpench-Vault`。
- 正式交付物仍为 WPS Word/Excel/PPT；工作台管理版本和索引。
- 双向实时同步：工作台写入 Obsidian 后打开即见；Obsidian 内修改、移动、删除也回读更新。

## Obsidian 最小目录

收件箱 / 项目 / 需求 / 知识 / 交付物 / 模板。

## 目录导入与迁移

- 用户可直接给目录，AI 读取后分类录入。
- 全量迁移：1.3GB 过往文件一次性复制进 Vault，原始文件夹保留且不自动删除。
- 支持 Word、Excel、PPT、PDF、Markdown、图片 OCR；其他格式只登记元数据。
- 文件去重：哈希去重，相同文件只保留一份；疑似版本由用户确认。
- 迁移或批量处理前自动备份 Vault 和数据库，保留最近 3 次快照。
- 输出成功、失败、无法解析、待分类四类报告。

## 主对象与分类

- 客户和项目合并为一个主对象。
- 分类维度：主对象 -> 文档类型 -> 业务阶段。
- 主对象字段：名称、状态、来源/商务、需求摘要、负责人、关键 DDL、关联本地文件夹、关联交付文档、待办、风险。
- “商务”是客情沟通岗位；无移交状态机，口头介绍后直接对接，仅保留轻量“来源/商务”文本。

## 需求与任务

- 主对象下挂“需求 -> 任务”两层。
- 需求单字段：类型、负责人、优先级、计划开始/结束、实际开始/结束、依赖、状态、关联文档、标准版/个性化开发标记。
- 任务字段：执行人、计划日期、实际日期、依赖、阻塞原因。
- 客户/项目档案只展示汇总：需求数、未完成数、最近 DDL、风险。
- AI 先从一句话需求生成“需求工作卡”：归属、需求摘要、待办、建议 DDL、依赖、风险、待确认问题。
- DDL 和待办先作为建议，用户确认后进入正式计划；无 DDL 标为需补充。

## 项目管理

- 甘特图和自动排期：按任务依赖、优先级、预计工期、工作日计算。
- 延期时 AI 提示受影响任务并给顺延建议，不静默修改已确认计划。
- 不做资源负载预测。
- 项目档案包含里程碑、任务清单、负责人、DDL、风险、交付物状态。

## 文档生成

- AI 可直接生成最终 Word、Excel、PPT，用户确认后才另存为正式文件。
- 文件名：`客户/项目-文档类型-日期.docx/.xlsx/.pptx`，原始文件不覆盖。
- 编辑用 WPS 打开，工作台不内置 Office 编辑器。
- AI 可读取指定历史 WPS 文件作为模板和风格来源，不修改原文件。
- AI 输出文档体检和优化版本，用户确认后另存新文件。
- 版本、生成时间、确认人写入 Obsidian。

## 需求池交付

- 需求池直接放在工作台，不再依赖飞书。
- 导出：Excel 需求池 + Markdown/HTML 详情文件包，相对链接可点击跳转。
- 开发可通过共享目录、代码仓库或飞书查看，不需要访问工作台本机。
- 飞书需求池首版通过复制或导出进入收件箱；不做 API 自动同步。

## 测试与缺陷

- 自动生成测试用例：编号、标题、模块、前置条件、测试数据、步骤、预期、自动化标记、优先级。
- 导出 Excel + JSON，供后续自动化测试工具复用。
- 轻量缺陷管理：项目、模块、严重级别、现象、复现步骤、期望行为、状态、关联需求/用例。
- 首版不自动执行测试，不代替用户放行。

## 原型与标注

- AI 生成可交互 HTML 高保真原型：页面布局、字段、状态、关键交互。
- 导出截图和设计说明。
- 集成用户已有的“原型标注 skill”，用于在原型上标注需求描述等内容；skill 从另一台电脑提供后适配。
- skill 未到位前，原型先使用标准标注字段占位。

## 运营与对账

- 运营模块包含：月度对账、运营数据导入、周报/复盘初稿。
- 对账数据由用户每月下载随行付和系统后台 Excel 后导入。
- 对账最小粒度：日期 + 门店/账户；结算单只有每日总额时，先做日期总额差异，再逐店排查。
- 对账口径：按账户配置，例如随行付学校结算额对系统后台“学校收入”；平台/商户收入分别配置。
- 字段名不同时由用户配置一次映射并记住。
- 输出对账报告 Excel + Obsidian 记录；一致归档，差异生成待核对任务。

## 二开与模块地图

- 每个项目建立系统模块地图：原系统资料、模块、页面、流程、接口/数据表、历史需求、已做改动。
- 区分标准版基线与二开差异。
- 需求标记：标准版配置、个性化开发、标准版升级、缺陷修复；提示升级冲突或回归风险。
- 支持用户提供源码目录，AI 只读分析路由、页面、接口、数据表、模块目录，不修改源码、不读取密钥。
- 模块地图由 AI 从历史资料和源码自动生成，用户审核补正，后续处理需求时持续更新。

## AI 自动化边界

- 自动：读取指定目录、分类、生成初稿、更新 Vault、提出待办/DDL、风险提醒、调用记录、文档体检、对账匹配。
- 需确认：正式 DDL、最终文档确认/另存、报价和金额、需求状态变更、任务关闭、发送微信/飞书/邮件。
- 首版不做微信/飞书自动推送；提醒在今日视图、项目驾驶舱、Obsidian 中展示。

## AI 学习与进化

- 记录用户接受、修改、拒绝 AI 输出的行为，以及手动调整的字段、模板、排期、文档结构。
- 反复出现的偏好沉淀为“个人规则”，带来源、适用场景、置信度；重要规则需确认。
- AI 不能静默改写事实，不能把单次特殊情况当成通用规则。
- 从过往文件学习客户/项目、术语、模板、表格字段、分账/对账口径、交付习惯。

## 模型与安全

- 主模型：DeepSeek 云端 API；设置页提示“数据将发送至云端”，保留调用记录。
- API Key 存 Windows 凭据管理器或环境变量，不写入 Vault、项目、数据库或日志。
- 只读取用户明确指定目录、Vault、导入区，不静默扫描全盘；每次调用显示路径和数量。
- 处理范围：Office、PDF、Markdown、图片 OCR；其他格式仅登记。

## 界面模块

今日工作、统一收件箱、客户/项目、需求与任务、文档、知识库审核、设置。

交互以对话为主 + 结构化卡片确认，支持粘贴微信文字、拖入文件、选择目录和源码路径。

## 验收标准

1. 用户逐项验证本文件中“前面沟通内容”全部达到预期，才算 T001 验收通过。
2. 端到端场景：提供目录或源码路径 + 一句需求，AI 生成需求工作卡、模块影响、排期/甘特图、测试用例、HTML 原型、方案/清单文档初稿，并同步 Obsidian；用户确认后另存。
3. 对账场景：导入随行付和系统后台 Excel，生成对账报告、差异任务并同步 Obsidian。
4. 全量迁移场景：1.3GB 文件复制进 Vault，原文件保留，去重、OCR/解析、分类报告完整。
5. 连续使用四周成功指标：资料查找时间下降 60%、文档初稿准备时间下降 50%、月度对账时间下降 70%、手动搬运减少 80%。
6. 所有敏感数据、API Key、调用日志符合安全要求。
