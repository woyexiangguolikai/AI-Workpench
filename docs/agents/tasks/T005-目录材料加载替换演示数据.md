## 目标

修复“可以选择目录，但工作台内容仍是代码内置演示数据”的问题。选择目录后，工作台应基于用户实际目录中的文件加载材料，并让文档、收件箱、客户/项目、需求/任务等模块展示真实文件信息或明确的空状态，而不是继续展示 `src/data.ts` 中写死的示例内容。

## 用户反馈

1. 目录选择功能已经可以正常打开目录。
2. 选择目录后，顶部路径和扫描统计会更新。
3. 但文档、客户/项目、收件箱、知识库等页面内容仍是代码里预置的演示数据。
4. 用户希望工作台根据实际上传/选择的材料变化。

## 本任务边界

- 本任务只做本地真实文件加载、基础分类和界面数据联动。
- 不做 AI 深度分类、OCR、自动生成 PRD、Obsidian 自动同步、自动对账和自动报价。
- 浏览器预览模式可以继续使用演示目录，但 Electron 桌面模式必须读取实际目录。

## 需要实现的链路

1. 目录选择成功后，Electron 主进程返回目录中的真实文件列表，包括文件名、路径、扩展名、文件大小和修改时间。
2. 渲染进程将真实文件映射到工作台数据：
   - 文档页：展示实际 Word/Excel/PPT/PDF/Markdown 文件；
   - 收件箱：将扫描到的材料作为“本地材料”条目展示，或显示真实空状态；
   - 客户/项目：根据所选目录或一级子目录生成项目/资料卡片，不再显示硬编码项目；
   - 今日工作、需求与任务、知识库：显示基于真实材料得到的候选信息或明确空状态。
3. 切换目录时，业务模块数据同步更新。
4. 原有静态演示数据只能作为浏览器预览模式或首次未选择目录时的回退数据。

## 验收标准

1. 在 Electron 桌面模式选择包含实际文件的目录后，文档页展示该目录中的真实文件，不再只显示 `data.ts` 示例文档。
2. 客户/项目页展示基于所选目录或一级子目录生成的真实材料来源，不再硬编码 `北城医科大学`、`华东国企园区`、`同济医院` 等示例项目。
3. 收件箱、今日工作、需求与任务、知识库页面在无真实材料时显示清晰的空状态，不出现与所选目录无关的示例内容。
4. 切换目录后，上述页面数据同步刷新。
5. 扫描结果和文件列表应经过路径白名单校验，不读取用户明确选择目录之外的路径。
6. 增加自动化测试，覆盖：
   - 主进程目录文件列表接口；
   - 真实文件到文档/项目/收件箱数据的映射；
   - Electron 模式下选择目录后文档页出现实际文件名；
   - 浏览器预览模式仍可使用演示数据。
7. `npm.cmd test` 全部通过，`npm.cmd run build` 通过。
8. 不写入 API Key、密码或令牌，不调用外部 AI 服务。
